# 面试逐字稿：Resume Agent FastAPI Demo（寒假 Demo 主作品）

讲法：按"用户→场景→问题→价值→决策→结果"展开，先讲业务价值，再讲技术实现；
每个技术点都准备一句"为什么这么做"，追问来了直接接住。

## 一、用户

求职者：手里有一份基础简历，要投不同岗位，每次都得手工改，还怕改出编造内容。
招聘方视角：收到的简历经常"看起来很强，面试一问就穿帮"。

## 二、场景

用户粘贴基础简历 + 岗位 JD，点"开始分析"：系统先建事实账本，再对 JD 做
匹配分析；用户确认事实、回答深挖问题后，才生成定向简历，并能导出 PDF。
整个过程里，未确认的事实不会进入最终稿。

## 三、问题

市面上的简历改写工具（包括直接调大模型改写）有两个硬伤：
1. 编造：模型会把"参与"写成"主导"，把"了解"写成"精通"，面试一追问就露馅；
2. 不可查：改完不知道每句话的证据在哪，出了问题没法回溯。

## 四、AI 带来的价值

- 事实账本 + Claim Ledger：简历先拆成原子事实（C001…），每个 Claim 挂证据、
  角色等级、风险标记；改写只允许降级（"主导"可降成"参与"，反向不行），
  从机制上堵住夸大。
- 匹配矩阵 + ATS 三档评分：JD 要求逐条打直接/可迁移/缺口，ATS 按
  blocker（硬上限）/warning（扣分）/tip（不计分）三档出分，缺口明明白白。
- 面试防御：每个强表述自动配追问和回答边界，用户提前知道面试官会怎么问。

## 五、关键决策（追问高发区，重点准备）

1. **为什么不用 Gradio、改用 FastAPI？**
   原服务是标准库 http.server 手写，只能单进程跑演示；FastAPI 层是新增的
   `api_fastapi.py`，与原端点一一对应，改动零侵入——老服务、老测试一个字没动。
   FastAPI 带来三样东西：标准 OpenAPI 文档、类型校验、以及可被其他服务调用的
   HTTP 接口，这是"演示"变"可集成产品"的分水岭。
2. **为什么用 SQLite 而不是内存？**
   原任务存在进程内存字典里，重启就丢；Demo 把会话、主张账本、拷打记录落盘，
   面试时能当场 `sqlite3` 查出来：哪次分析产了哪些 Claim、深挖问了几轮、每轮
   补了什么。落盘是观测手段，不是新门禁——写库失败只记日志，不阻断主流程，
   这个取舍是故意设计的。
3. **Agent 化到底改了什么？**
   原来深挖是一次性出 3 个问题；现在是 Thought→Action→Observation 的多轮循环：
   每轮先用工具算覆盖缺口（哪个高风险 Claim 没被面试防御覆盖），再用工具取
   下一个问题，拿到回答后转 Claim、重算覆盖，直到缺口清零或达到最大轮次。
   工具是 langchain_core 的 @tool，循环每轮的 thought/action/observation 全记日志。
4. **没有模型密钥时怎么办？（诚实点，别吹）**
   本地演示默认没有模型密钥，循环走规则回退：问题沿用 question-tree 原问题，
   响应里 `llm_used=false`、`mode=rule_fallback`，日志也这么记。
   架构上模型调用已接好（复用 `llm_client.call_llm`），有密钥即切 LLM 改写问题；
   没密钥也不中断、不编造——"没调过模型"这句话，面试时要自己先说出来。
5. **安全机制为什么原样保留？**
   PR #4 的教训：重写文件时丢过三处安全机制，被 CI 抓回来。
   所以这次只新增文件：loopback 绑定、Content-Type 校验、任务查询剥离简历/JD
   原文，三处全部复用原函数，没重写、没"优化"。

## 六、最终结果（数字要对得上口径）

- 全量测试：改动前 122 个，改动后 132 个（新增 10 个 Demo 层测试），
  老测试一个没少、一个没挂；无 fastapi 的环境新测试自动跳过。
- 端点：FastAPI 层 8 类端点全部 curl 实测通过（PDF 渲染除外，见下）。
- 落盘：SQLite 文件可查，会话、账本、拷打记录三张表都有数据。
- Agent：多轮循环日志可查，规则回退模式如实标记。

## 七、主动说明的短板（别等面试官挖）

### 本轮已修（P1 全修轮，有测试覆盖）

- 请求体上限与错误码：FastAPI 层补了 2MB 上限，畸形 JSON 统一返回 400，
  与原服务口径一致（之前是 FastAPI 默认 422、无上限）。
- store 接口不再返回原文：claim 全文与问答原文只存库内，接口只返会话元数据、
  claim_id、结构化 risk_flags、轮次元数据与计数；拷打记录库内 question/answer
  全文保真，连续分析→深挖不丢账本。
- Agent 诚实性补齐：未匹配 question_id 的回答明列 ignored，不静默丢弃；
  停止原因 stopped_reason 区分问题池耗尽与跑满轮次（问题池每快照最多 3 个
  不同问题，max_rounds>3 也可能提前停止，这个上限语义要主动讲出来）。

### 仍未验证（继续保留，不冒充）

- PDF 渲染硬编码服务器字体目录 `/opt/demo/resume/fonts`，本机无此目录时
  PDF 端点不可用——这是既有部署耦合，本分支刻意没动它（动部署目录是红线），
  已在 README 里写明；PDF 端点的接线用 404 路径测过。
- Agent 循环的 LLM 真调用尚未验证（本地无密钥），演示时讲规则回退路径；
  有密钥的环境一换就能走 LLM 分支，代码路径同一条。
