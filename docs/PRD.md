# Resume Agent 产品需求文档（PRD）

- 版本：v1.0
- 日期：2026-10-01
- 作者：肖学炀（独立完成需求分析、产品设计与实现）
- 状态：已实现 MVP（本地单用户），见仓库 README；本文档沉淀需求与验收口径

---

## 1. 背景与目标

### 1.1 问题

求职者用 LLM 做"JD 定向简历改写"时，模型经常：

- 把 JD 里的要求直接写成候选人的事实（事实混用）；
- 编造或迁移数字、日期（数字失真）；
- 输出不可追溯——哪句话是改写的、依据是什么，无从查证。

后果：投递出去的简历与本人真实经历不符，背调或面试时露怯。

### 1.2 产品目标

做一个"真实性门禁"优先的简历改写 Agent：

1. 任何改写必须绑定可审计的证据（事实账本），无证据不写；
2. 数字、日期、强断言走独立门禁校验，触发即拦截；
3. 全链路产物可验证、可回滚、可复现（manifest + 哈希）。

### 1.3 非目标（当前版本不做）

- 不替候选人核实事实真伪（只保证"改写不超出输入事实"）；
- 不承诺 ATS 评分、面试结果或录用结果；
- 不做公网多用户服务（当前为本地单用户 MVP）。

---

## 2. 用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 求职者（校招/社招） | 拿到目标岗位 JD，想快速得到一份"贴合 JD 但不造假"的简历 | 改写可信、每句话有据可查 |
| 求职者（多投递） | 同一份底稿要投多个不同岗位 | 一次输入，多次定向，版本可管理 |

典型流程：粘贴简历 + JD → 查看事实账本与待确认问题 → 确认证据 → 生成定向简历 → 下载 Markdown / PDF / PNG。

---

## 3. 功能需求

### 3.1 输入与事实账本（Fact Ledger）

- FR-1.1：接受纯文本简历与 JD 输入（UTF-8）。
- FR-1.2：从简历抽取结构化事实账本，每条事实编号（`F001…`），作为后续一切改写的唯一证据源。
- FR-1.3：从 JD 动态抽取关键词（中英文词边界匹配 + 通用噪声过滤）；复杂 JD 只抽取可审计的已知能力概念与英文工具/证书名，不把标题、连接词或残句生成为"要求"。

### 3.2 岗位分析与证据映射

- FR-2.1：岗位要求分类为硬性条件 / 优先条件 / 岗位职责三类。
- FR-2.2：每条要求映射到事实账本编号，标注：直接命中 / 部分命中 / 需人工核对。
- FR-2.3：对证据不足的要求生成待确认问题（`confirmation-questions.md`），用户确认前不写入简历。

### 3.3 改写与真实性门禁（核心）

- FR-3.1：改写工作流：事实提取 → 岗位分析 → 改写证据校验 → 定稿 → 真实性校验（支持纯 Python 默认路径与 `--workflow langgraph` 可选编排）。
- FR-3.2：每条模型改写必须携带 `evidence_ids`，且只能引用事实账本中存在的编号；引用无效证据的改写不得进入终稿。
- FR-3.3：数字、日期、强断言走独立门禁：缺证据、无证据或触发强断言的改写一律拦截。
- FR-3.4：禁止把 JD 要求、模型建议或推测直接写成候选人事实。
- FR-3.5：输出逐条改写差异报告（建议、证据、采纳/拒绝结果），可审计。

### 3.4 交付物

- FR-4.1：同步生成 ATS Markdown、单页 A4 PDF、PNG 预览与 QA 报告。
- FR-4.2：QA 门禁覆盖：页数、文字可提取性、越界、分辨率（图片动态高度、超长英文拆行、照片碰撞与边界检查）。
- FR-4.3：正文不低于约 10.5pt；一页放不下时明确要求精简低相关内容，不靠缩小字号硬塞。
- FR-4.4：交付包写入版本化快照目录（`releases/<release_id>/`），`current-release.json` 单文件切换权威版本；每次运行生成 `run-manifest.json` 与外置 `run-manifest.sha256` 校验。

### 3.5 本地 Web 工作台（MVP）

- FR-5.1：一键启动本地工作台（`web_app.py`），串起"粘贴简历/JD → 查看事实账本与待确认项 → 确认后生成 → 下载 Markdown"。
- FR-5.2：服务只绑定 `127.0.0.1:8765`，拒绝非回环地址；材料只在当前本机进程内处理。
- FR-5.3：页面使用本地规则工作流，不自动调用第三方模型；`--call-llm` 显式开启时才联网。

### 3.6 隐私与安全

- FR-6.1：示例目录只放脱敏数据；真实简历、JD、照片、模型输出不提交到公开仓库。
- FR-6.2：API Key 只从环境变量读取，不写入代码、日志与输入文件；`.env.example` 仅为变量名示例。
- FR-6.3：LLM 接口错误脱敏；不输出响应正文、提示词或密钥；运行时不落盘完整提示词。
- FR-6.4：密钥经 SecretRef 引用不落盘；输出目录拒绝符号链接。

## 4. 非功能需求

- NFR-1（可审计）：任何终稿句子可回溯到事实账本编号；改写差异报告完整。
- NFR-2（可复现）：同输入同参数下产物一致；manifest 哈希可校验。
- NFR-3（诚实失败）：证据不足、页数超限、解析失败时明确报错并给出处理建议，不静默降级。
- NFR-4（本地优先）：默认不联网；联网能力均为显式开关。

## 5. 验收标准（MVP 已达成）

| 验收项 | 口径 | 状态 |
|---|---|---|
| 事实账本 | 简历输入可抽取编号事实，改写 `evidence_ids` 全部命中账本 | ✅ 已实现 |
| 门禁拦截 | mock 运行可拦截无证据改写（示例：2 条） | ✅ 已实现 |
| 证据映射报告 | 终稿逐条标注直接命中/部分命中/需人工核对 | ✅ 已实现 |
| QA 门禁 | 页数、文字提取、越界、分辨率检查通过 | ✅ 已实现 |
| 版本快照 | releases 快照 + current-release.json 切换 + manifest 哈希 | ✅ 已实现 |
| 本地工作台 | 127.0.0.1:8765 可走完"粘贴→确认→生成→下载" | ✅ 已实现 |
| LangGraph 路径 | 真实节点：事实提取、岗位分析、改写证据校验、定稿、真实性校验 | ✅ 已实现（可选依赖） |

已知边界（非缺陷，属当前定位）：

- Web 工作台为单用户本地 MVP：任务状态存内存、PDF/PNG 交付包与 DOCX/PDF 导入属下一阶段；
- 未做公网部署、多用户、任务历史持久化。

## 6. 路线图（下一阶段）

1. 真实模型确认流程：把"待确认问题"做成可交互的确认流（当前为 Markdown 输出）。
2. DOCX / PDF 简历导入。
3. 工作台交付包导出（PDF/PNG）与任务历史。
4. 评测集：构造"故意缺证据 JD"对抗用例，量化门禁拦截率与误伤率。

---

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 模型幻觉绕过门禁（如改写措辞规避关键词检查） | 门禁基于事实账本编号引用而非关键词，措辞变化不影响判定 |
| 用户输入的"事实"本身就是假的 | 明确产品边界：只保证不超出输入事实，不做背调；投递前须本人复核 |
| 本地模型调用泄露简历隐私 | 默认不联网；`--call-llm` 显式开启并在 README 警示数据政策 |
